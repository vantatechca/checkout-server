1Overview

WPay 2D is a credit/debit card payment option processed through a WordPress + WooCommerce site running the WPay Channels plugin. The checkout server creates a WooCommerce order via the WC REST API, redirects the customer to that order's pay-for-order page (WPay Channels' own card form, tokenized via Basis Theory — raw card data never touches the checkout server), and WooCommerce fires a webhook back when the order's status changes.

This is a separate integration from services/wpay.py (the WPay HPP flow, gated by WPAY_ENABLED) — both can be enabled at once.

2Architecture

Customer → checkout-server (pepscheckoutportal.com)
  → POST /api/checkout/wpay_2d
  → creates local Order row (payment_method = wpay_2d)
  → creates WooCommerce order via REST API on wpay.pepscheckoutportal.com
  → redirects customer to WC's pay-for-order page
  → customer enters card on WPay Channels' tokenized form
  → WooCommerce fires webhook → POST /webhooks/wpay_2d
  → checkout-server marks local order paid/failed, creates Shopify order,
    fires affiliate webhook

No Celery fallback task exists for wpay_2d yet (unlike the HPP flow's 45-minute poll) — this path currently relies on the webhook firing reliably.

5nginx & wp-config.php

Two nginx server blocks exist for the WordPress site:

  • Legacy — /etc/nginx/sites-available/wordpress-wpay, port 8080, bare IP access. Still present, not removed.
  • Current — /etc/nginx/sites-available/wpay-domain, ports 80/443, real domain, HTTPS auto-configured by certbot.

Both include this required line (nginx doesn't forward the Authorization header to PHP-FPM by default — needed for Application Password auth):

fastcgi_param HTTP_AUTHORIZATION $http_authorization;

Added to wp-config.php:

define( 'WP_ENVIRONMENT_TYPE', 'local' );
define( 'WP_HOME', 'https://wpay.pepscheckoutportal.com' );
define( 'WP_SITEURL', 'https://wpay.pepscheckoutportal.com' );

WP_ENVIRONMENT_TYPE=local was needed to unlock Application Passwords before real HTTPS existed. No longer strictly required now, but harmless to leave.

WPAY_WP_STORES=victoriapeps.ca
  • ONRAMP_WP_ENABLED=false is intentional — the onramp_wp integration itself stays off; only the WPay 2D gateway (which reuses this site's URL/creds) is active.
  • WPAY_WP_STORES is a comma-separated allowlist of storefronts that see this option. Currently only victoriapeps.ca.
  • Minimum order: $5 USD (services/wpay_wp.py:MIN_AMOUNT), enforced server-side.

8Database migration required

python -m migrations.add_wpay_2d_to_payment_method_enum

Widens the orders.payment_method ENUM to accept 'wpay_2d'. Idempotent. Was missing on this VPS initially — caused a 500 on every checkout attempt until run.

9Frontend styling

Custom theme "WPay Checkout" is active. Additional CSS applied via Appearance → Customize → Additional CSS: centered card layout, styled order table, calmer guest-order notice, wider container (prevents card/expiry/CVC fields from cramping), emphasized Total row, trust signal below the Pay button.

Known open item: the "Payment method: Credit / Debit Card" summary row still shows — the CSS selector guess to hide it didn't match this theme's actual markup. Needs the real class (inspect-element) to fix precisely.
